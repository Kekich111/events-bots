# Боты мероприятий (Telegram + VK, одна БД)

Два бота работают поверх общего ядра и одной базы SQLite (`data/bot.db`).

```
tg_bot.py     — Telegram (aiogram 3)
vk_bot.py     — VK (vkbottle 4)
scheduler.py  — еженедельный дайджест (отдельный процесс)
core/db.py        — схема БД, пользователи, очередь исходящих (outbox)
core/commands.py  — вся логика команд (общая для обоих ботов)
```

## Запуск

```bash
pip install -r requirements.txt
cp .env.example .env        # заполнить токены и ID организаторов (бот читает .env сам)

python tg_bot.py &
python vk_bot.py &
python scheduler.py &
```

- **Telegram:** токен у @BotFather.
- **VK:** сообщество → Управление → Работа с API → ключ доступа (права на сообщения); в «Сообщения» включить сообщения сообщества, в Long Poll API — событие «входящие сообщения».
- Организатор должен хотя бы раз нажать /start в Telegram-боте (иначе Telegram не даст боту писать ему первым); в VK — разрешить сообщения от сообщества.

## Как это работает

- **Одна БД:** все данные (пользователи, мероприятия, команды, обращения) лежат в одном файле. Боты — тонкие адаптеры: передают текст в `core.commands.handle()` и показывают ответ.
- **Рассылки между соцсетями:** ядро кладёт сообщения в таблицу `outbox`, каждый бот забирает свою платформу. Поэтому мероприятие, созданное в Telegram, уходит и подписчикам VK.
- **Связка аккаунтов:** `/link` в одном боте даёт код, `/link КОД` в другом объединяет профили (команды и обращения становятся общими). Уведомления связанному пользователю идут в Telegram, без дублей.

## Что умеют

Всё делается **кнопками**: меню внизу (Мероприятия, Мои команды, Подписка, Поддержка; у организаторов ещё «➕ Мероприятие», «🎫 Обращения», «📢 Рассылка») и кнопки под сообщениями. Текстовые команды тоже работают.

**Участники:** выбрать мероприятие → «Вступить» или «Создать свою команду» (бот спросит название) → «Мои команды». Ссылки вида `/event_3`, `/join_5` кликабельны в Telegram.
**Поддержка:** кнопка «🆘 Поддержка» (или любое сообщение без `/`) — обращение уходит организаторам, они отвечают из бота кнопкой «Ответить». Выйти из диалога: `/cancel`.
**Организаторы:** «➕ Мероприятие» — мастер из 5 шагов (название, дата, место, описание, сколько людей ищем); «🎫 Обращения» — список, ответить, закрыть; «📢 Рассылка»; `/event_del <№>`.
**Рассылки:** при создании мероприятия — сразу; дайджест ближайших мероприятий — раз в неделю (по умолчанию понедельник 10:00, настраивается в `.env`).
**Связка аккаунтов:** `/link` в одном боте даёт код, `/link КОД` в другом объединяет профили.

## Деплой через Docker / Coolify

В проекте есть `Dockerfile` и `docker-compose.yml` (три сервиса: `tg-bot`, `vk-bot`, `scheduler`, общий том `bot_data` для БД).

1. Выложите проект в Git-репозиторий (файл `.env` не коммитьте — он в `.gitignore`).
2. Coolify → Project → New Resource → ваш репозиторий → Build Pack: **Docker Compose**, файл `/docker-compose.yml`.
3. Вкладка Environment Variables: `TG_TOKEN`, `VK_TOKEN`, `ADMIN_TG_IDS`, `ADMIN_VK_IDS` (остальное необязательно: `TZ_NAME`, `DIGEST_DAY`, `DIGEST_HOUR`, `DIGEST_DAYS`).
4. Deploy. Домен и порты не нужны: боты сами опрашивают серверы Telegram и VK.

Нужен только один бот — удалите ненужный сервис из `docker-compose.yml`. Для резервной копии сохраняйте файл `bot.db` из тома `bot_data`.

## Идеи для развития

Напоминания за сутки до мероприятия, веб-админка, PostgreSQL вместо SQLite при большой нагрузке, подтверждение участия.
